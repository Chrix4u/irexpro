## Implementation

- Added pure `apps/api/src/modules/ai/owner-demo-predispatch-fee-confluence-shadow.ts` (artifact `owner-demo-predispatch-fee-dual-abstain-research-v1`). No broker API, no DB calls, no model mutations and no authority over `canExecute` or `submitPaperDecision`.
- Wired it into `m1-tactical-scheduler.service.ts` at the precise point **BEFORE** the existing durable `evidence.recordDecision()`, and therefore **BEFORE** any `submitPaperDecision()` order call.
- Scope: owner configured as `VPS_FOREX_SCANNER_USER_ID`, broker independently verified by **both** `isPepperstoneDemoBrokerConnection` through the existing advisory path and `isPepperstoneUsdDemoBrokerConnection` through the existing FULL_AUTO owner session loss-advisory check when an actual loss brake is active; otherwise a narrowly scoped, **read-only** call to the existing exact USD DEMO account verifier for an already qualified owner reversal. This adds no broker order call and a verifier failure only abstains from research. The scope also requires the exact owner and Pepperstone USD DEMO professional phase, runtime feature `IREXPRO_OWNER_DEMO_PREDISPATCH_FEE_CONFLUENCE_SHADOW=enabled`. A missing flag or failed verification produces no valid owner-DEMO prediction. This independent rule never applies to LIVE.
- For an already admitted candidate whose final Plan-B route is `CONFIRMED_REVERSAL`, label a **research-only** `FEE_DEFICIT_DOUBLE_ABSTAIN_CAUTION` if (1) the existing as-of prior same demo broker fee sample count is at least 12 and the broker-native fee p90-adjusted net expected R is below the existing positive floor; (2) M1 tactical specialist is `ABSTAIN`; (3) independent trained expert is also `ABSTAIN`. Raise observational label `FEE_DEFICIT_DOUBLE_ABSTAIN_WITH_INDEPENDENT_CONFLICT` if additional causal completed H1/M5 opposition or mature already-closed negative-payoff strategy evidence is present. The negative-payoff records are already available at decision time. Never invent missing evidence.
- Non-Confirmed Reversal routes are controls. Unadmitted candidates are explicitly `NOT_SELECTED_FOR_DISPATCH`; no post-dispatch judgment can convert them to broker trades.
- Persist the complete as-of research label into the existing `trading.m1_tactical_decisions.governance.ownerDemoPreDispatchFeeConfluenceShadow` **before** the order attempt. It carries `evaluationPhase:BEFORE_DURABLE_DECISION_AND_BEFORE_ORDER_DISPATCH`, `noOrderBlock:true`, `noLotSizingChange:true`, `noExitAuthority:true`, `noStopChange:true`, `noLivePromotion:true`, `noCounterfactualSavedMoney:true`.
- Added `owner-demo-predispatch-forward-score.cjs` as a pure verifier and joined that persisted warning into the **already deployed independent 45-second broker-settlement scorecard**. A trade is valid as a *pre-dispatch* warning only when the associated decision was recorded and evaluated before its broker opening timestamp, the frozen owner's DEMO trade and decision match by exact trade-intent and broker connection, the warning artifact and its non-authority flags match, and the stored decision timestamp is causally consistent. The report tracks broker-net after actual commission+swap, open and closed positions, warnings that won (false positives), clean controls and other strategies. Old trades with no research label remain `NOT_INSTRUMENTED_BEFORE_RESEARCH_DEPLOYMENT`, NOT retroactive successes.
- This does not record unfilled candidates as 'losing trades' or assert hypothetical broker execution for any blocked candidate. It cannot calculate real savings from hypothetical abstention because fills and exit prices in the counterfactual were never observed.

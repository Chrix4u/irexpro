# Pepperstone DEMO protected runner stop-readiness, shadow only (18 November 2026)

The actively used profit protector closes via provider close requests; do not delay that close or change broker SL/TP based on an approximate trend forecast. The pre-existing `protected-runner-shadow` computed only an indicative proposed stop using original risk geometry, and could not establish broker tick size, minimum stop distance, precise P&L-to-price conversion, or amendment confirmation.

This research change adds the `verified-profit-runner-stop-shadow` reviewer to the already asynchronous, **post-protective-close** trend-recheck audit. It records a second, independent stop-readiness assessment requiring exact Pepperstone DEMO identity, owner USD account, M1 alternate route, original broker stop and TP equality, exact provider symbol/position side/lot, valid/monotonic positive stop, recent positive broker-native bid/ask (<=15 sec), normal spread, positive after-extra-fee-and-slip modeled stop payout, and a profitable candidate trend from the earlier read-only runner. Every result is labelled `SHADOW_ONLY`, `modifiesExecution=false`, `noTradeAuthority=true`, `brokerStopUnchanged=true`. The proposed stop price is **not executable**.

A passing research candidate explicitly reports `REQUIRES_BROKER_TICK_MIN_STOP_AND_AMENDMENT_VERIFICATION`: actual tick increments, provider stop-distance constraints, currency P&L conversion, persistence, idempotency, broker authorization and the independent amend/verify/reconcile pipeline all remain unimplemented. The historical as-of bid/ask query is scoped to the already matched broker connection, instrument and decision timestamp. Missing data rejects readiness, never substitutes future or zero quotes. No extra broker modification calls and no change to existing profits, SL/TP or LIVE accounts.

Verification: 110 Jest tests across existing profit protector, previous runner and new readiness helper; TypeScript build configuration checks passed. Assess real unchanged profit-lock exits against independent subsequent price paths and actual commission/slippage before proposing a broker-side protected runner rollout. Do not claim this proves profitability.
